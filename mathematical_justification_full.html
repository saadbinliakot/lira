Mathematical Justification — Why These Specific Choices?

OLS · Chow Test · Recursive Tree · BIC · PC Algorithm — why each one, why not alternatives, grounded in black hole accretion disk data.

what your data looks like
Variables (all in log scale): L_X = log X-ray luminosity (predictor) Γ = photon index (predictor) T_in = inner disk temperature (predictor) HR = hardness ratio (predictor) F_R = log radio flux (RESPONSE — what you predict) n = 800 observations Each row = one telescope measurement epoch
why OLS specifically — the physical justification

Black hole accretion disk physics follows power laws:

F_R ∝ L_X^β₁ · T_in^β₂ · ... Taking log of both sides: log(F_R) = β₁·log(L_X) + β₂·log(T_in) + ... Which is: F_R = β₁·L_X + β₂·T_in + ... (in log space) = EXACTLY a linear model

This is why you work in log space. Power law physics becomes linear regression. OLS is therefore the exact right tool — not an approximation.

the OLS derivation — why this formula
You want the best-fitting line through your data. "Best" = smallest total squared error. Loss function: L(β) = Σᵢ (F_Rᵢ − Xᵢ·β)² = ||Y − Xβ||² Minimize by taking derivative and setting to zero: dL/dβ = −2XᵀY + 2XᵀXβ = 0 Solve: XᵀXβ = XᵀY ← Normal Equations β̂ = (XᵀX)⁻¹ XᵀY ← OLS estimator
why not other regression methods?
Ridge / Lasso — why not
Ridge and Lasso add a penalty term λ||β||² to shrink coefficients. You don't want shrinkage — you want the TRUE coefficient values so the Chow test can compare them accurately. Shrinkage would bias the comparison.
Polynomial regression — why not
Your power law physics is already linear in log space. Adding polynomial terms would overfit and make the Chow test mathematically inconsistent — the degrees of freedom calculation would break.
Neural network — why not
No closed-form solution. Cannot compute RSS analytically. Cannot do the Chow F-test. Black box — no interpretable β coefficients to compare between regimes. Requires gradient descent — not deterministic.
OLS — why yes
Closed-form β̂ = (XᵀX)⁻¹XᵀY. Gives exact RSS. Enables Chow test mathematically. Interpretable β values. Gaussian noise assumption matches telescope measurement noise. Deterministic and reproducible.
your specific result — root node
β̂_global on all 800 obs: [intercept, L_X, Γ, T_in, HR ] [β₀, 0.107, -2.620, -13.007, 9.833] RSS_global = 1563.53 ← large, model struggling β(T_in) = -13 is physically nonsensical. β(HR) = +9.8 is also wrong. Reason: two opposite causal mechanisms averaging into meaningless global coefficients. This large RSS and nonsensical β is your SIGNAL that K=1 is wrong.
OLS is the foundation of everything. Without OLS you cannot compute RSS. Without RSS you cannot do the Chow test. Without the Chow test you cannot detect regime boundaries. OLS is not a choice — it is the mathematical prerequisite for everything that follows.
the core question your algorithm asks

Given two groups A and B of telescope observations — do they obey the same causal law or different ones?

H₀: β(A) = β(B) ← one physical mechanism H₁: β(A) ≠ β(B) ← different mechanisms, regime boundary here
why the Chow test — the physical justification

In the hard state, radio jet power is driven mainly by X-ray luminosity: β(L_X) ≈ +0.70. In the soft state, disk temperature drives it: β(T_in) ≈ -0.40, and β(L_X) drops to +0.18. These are COEFFICIENT differences — not distributional differences. The Chow test directly tests coefficient equality. It is built for exactly this.

the formula — where it comes from
Intuition: If β(A) = β(B) truly, then fitting one model on all data should be just as good as fitting two separate models. Cost of pooling = RSS_global − (RSS_A + RSS_B) If small → one model is fine → K=1 If large → two models are needed → K>1 Chow F-statistic: F = [RSS_global − (RSS_A + RSS_B)] / p ────────────────────────────────────── (RSS_A + RSS_B) / (n − 2p) Numerator: average cost of pooling per parameter Denominator: baseline within-group error per obs Under H₀: F ~ F(p, n−2p) p-value = P(F-distribution > F_observed)
your specific numbers — root node
Best split: T_in ≤ 0.6425 RSS_global = 1563.53 RSS_A = 89.3 (hard state, 400 obs) RSS_B = 94.7 (soft state, 400 obs) Numerator: (1563.53 − 184) / 5 = 1379.53 / 5 = 275.9 Denominator: 184 / (800 − 10) = 184 / 790 = 0.233 F = 275.9 / 0.233 = 13,864 p-value < 0.0001 → REJECT H₀ → β(hard state) ≠ β(soft state) → Two different physical mechanisms confirmed
why not other invariance tests?
KL Divergence — why not for P1
Measures difference between full probability distributions. Requires estimating the entire P(F_R|X) in each group — needs large sample. For n=400 per group and p=4, sample is too small for reliable density estimation. Chow test needs only means — far more efficient.
MMD (Max Mean Discrepancy) — why not for P1
Kernel-based nonparametric test. Powerful but requires choosing a kernel and bandwidth. No closed-form. Cannot directly test whether COEFFICIENTS β differ — only whether residual distributions differ. Loses the direct connection to causal mechanism comparison.
t-test on means — why not
Tests only whether mean of F_R differs between groups. Two groups could have the same mean F_R but completely different causal structures (different β). The t-test would miss the regime boundary entirely.
Chow test — why yes
Directly tests β(A) = β(B). Optimal under Gaussian noise (which telescope data follows). Exact F-distribution under H₀. Calibrated p-values. Closed-form computation. Scales with p naturally through its degrees of freedom.
two different uses of the Chow test in your algorithm
Use 1 — DETECTION (initial global check): Split randomly into A_rand, B_rand (50/50) If F is large → regime structure exists somewhere If F is small → K=1, stop Problem with random split: if regimes are mixed equally in each half → both halves look the same → F is small → algorithm MISSES the regime structure This is why the first code version failed (ARI=0). Use 2 — SEARCH (find exact boundary): Try every possible axis-aligned split (j, τ) Compute F for each Pick (j*, τ*) = argmax F This finds the split where mechanisms differ MOST This is the correct approach in your final code.
The Chow test was originally designed for time series structural breaks at KNOWN time points. Your innovation: apply it at UNKNOWN points across all candidate thresholds and pick the maximum. This repurposes a 60-year-old test for a new problem.
the fundamental question

Why build a tree at all? Why not just do one split and stop?

Answer: you don't know K in advance

For your synthetic data K=2 is correct. But on real Sgr A* data K might be 3 or 4 or 1. The tree lets the data determine K automatically. If one split is enough — the tree stops at depth 1. If three splits are needed — the tree grows to depth 3. The algorithm finds K, it does not assume it.

why recursive — not just one split
One split gives you two groups. But what if one of those groups contains ANOTHER hidden regime? Example on real data: Root split: T_in ≤ 0.6425 (hard vs soft) Inside soft state: another split at T_in ≤ 0.95 → sub-group A: soft/intermediate state → sub-group B: ultra-soft (near-Eddington) Result: K=3 discovered regimes Regime 0: hard state Regime 1: soft/intermediate state Regime 2: ultra-soft state Without recursion you would MISS the third regime. The tree found it by asking the same question inside each child.
why binary splits — not 3-way or k-way
k-way split — why not
Would need to search over all possible k-partitions. Exponentially more candidate splits. For k=3 you would evaluate n²·p² combinations — computationally infeasible for n=800. Also harder to interpret: "split into 3 based on what condition?"
Binary split — why yes
One threshold. One feature. One clear condition: T_in ≤ 0.6425. Interpretable physically. Computationally O(n·p) per node. Three-way splits emerge naturally from two levels of binary splitting if needed.
why axis-aligned — not diagonal or curved splits
Diagonal split — why not
Split on a linear combination: a·T_in + b·HR ≤ c. Exponentially more candidates. Loses interpretability: "the mechanism changes when 0.3·T_in + 0.7·HR crosses 0.5" means nothing physically.
Axis-aligned — why yes
Split on one variable at one threshold: T_in ≤ 0.6425. Physically meaningful. Directly interpretable: "the causal mechanism changes at inner disk temperature 0.64 keV." An astrophysicist can use this number immediately.
the recursive algorithm formally
LICP(node D, depth d): // Stopping conditions if d ≥ d_max: return LEAF (max depth) if |D| < 2·n_min: return LEAF (too small) // Step 1: search (j*,τ*) = argmax_{j,τ} F_chow(A(j,τ), B(j,τ)) s.t. |A|,|B| ≥ n_min // Step 2: validate if BIC(A*,B*) ≥ BIC(D): return LEAF (noise, not real) // Step 3: split D.left = LICPNode(A*, d+1) D.right = LICPNode(B*, d+1) // Step 4: RECURSE — independently on each child LICP(D.left, d+1) LICP(D.right, d+1)

why greedy — not global optimal
Finding the globally optimal partition is NP-hard

The true optimal partition minimizes total invariance violation across ALL nodes simultaneously. Evaluating all possible subsets of 800 observations = 2⁸⁰⁰ possibilities. Completely infeasible. Greedy search finds a locally optimal solution in O(n·p) time per level — tractable, and as ARI=1.0 proves, sufficient in practice.

the problem BIC solves

Without a stopping rule, the tree would keep splitting. Every group of 2 observations is trivially "invariant" — one point cannot disagree with itself. The algorithm would split 800 observations into 800 groups of 1. That is meaningless.

why BIC — the intuition
Splitting gains: better fit (lower RSS per group) Splitting costs: more parameters (2p instead of p) BIC formalizes this tradeoff: The improvement in fit must be large enough to justify doubling the parameter count. If the fit improvement is small (noise-driven): The complexity cost outweighs the gain → REJECT If the fit improvement is large (real regime boundary): The complexity cost is easily justified → ACCEPT
the formula
BIC for 1 model (no split): BIC₁ = n · log(RSS/n + ε) + p · log(n) ↑ fit quality term ↑ complexity: 1 model × p params BIC for 2 models (after split): BIC₂ = nA·log(RSS_A/nA + ε) + nB·log(RSS_B/nB + ε) ↑ fit quality in A ↑ fit quality in B + 2·p·log(n) ↑ complexity: 2 models × p params ACCEPT split if BIC₂ < BIC₁ (improvement justifies cost) REJECT split if BIC₂ ≥ BIC₁ (this node is a LEAF)
your specific BIC numbers — the critical demonstration
AT ROOT (n=800): BIC₁ = 800·log(1563/800) + 5·log(800) = 528.8 + 33.4 = 562.2 BIC₂ = 400·log(89.3/400) + 400·log(94.7/400) + 10·log(800) = -599.2 + (-577.2) + 66.8 = -1109.6 Drop = 1671.8 points → ACCEPT ✓ (real regime boundary) INSIDE REGIME 0 (n=400, best split HR≤0.776, F=28,967): BIC₁ = 400·log(89.3/400) + 5·log(400) = -569.3 BIC₂ = -561.8 BIC INCREASED by 7.5 → REJECT ✗ (noise, not real) INSIDE REGIME 1 (n=400, best split T_in≤1.206, F=28,705): BIC₁ = -547.3 BIC₂ = -539.1 BIC INCREASED by 8.2 → REJECT ✗ (noise, not real)
Most critical insight: F=28,967 inside Regime 0 is HIGHER than the root F=13,864 — yet BIC correctly rejects it. Inside a stable single regime of 400 hard state observations, random noise creates apparent coefficient differences. These are not real regime boundaries. BIC distinguishes genuine physical boundaries from statistical noise. Without BIC, your algorithm would over-split every dataset into meaningless groups.
why BIC — not other stopping rules
Fixed threshold δ — why not
Accept split if L_inv drops by δ. But δ is arbitrary. What should it be? Too small → over-splitting. Too large → under-splitting. Requires manual tuning per dataset. Not principled.
p-value threshold only — why not
Chow p-value < 0.05 → always split. Does not account for the cost of adding parameters. As n grows large, even tiny meaningless differences become statistically significant. Would massively over-split on large datasets.
AIC — why not
AIC = 2k − 2ln(L). Penalizes complexity less than BIC (uses 2 instead of log(n)). For n=800, log(800)=6.7 so BIC penalizes ~3× more than AIC. AIC tends to over-fit and over-split on your sample size. BIC is more conservative and correct here.
BIC — why yes
Derived from Bayesian model evidence (Schwarz 1978). Penalizes complexity by log(n) — scales automatically with sample size. No tuning required. Consistent — selects correct K as n→∞. Principled theoretical justification.
why you need a separate stage at all

OLS gives you β̂(k) — regression coefficients for each regime. These tell you that L_X predicts F_R in Regime 0. But β is NOT a causal graph. It does not tell you which causes which. Two variables can be correlated (both predicted by a third) without either causing the other.

OLS tells you: F_R = 0.70·L_X − 0.22·Γ − 0.04·T_in − 0.52·HR + ε This says: L_X, Γ, T_in, HR all predict F_R. It does NOT say: L_X causes F_R. It does NOT say: the arrow points L_X → F_R. HR could be causing L_X which causes F_R. Or all three could be caused by an unobserved fourth variable. OLS gives regression. PC gives causation. You need both.
how the PC algorithm works on your data
Step 1 — Start fully connected
Every variable connected to every other variable (undirected): L_X — Γ — T_in — HR — F_R All pairs connected. No directions yet.
Step 2 — Remove edges via conditional independence
For each pair (Vᵢ, Vⱼ): Test: Vᵢ ⊥ Vⱼ | S for conditioning sets S Example in Regime 0 (hard state): Test T_in ⊥ F_R | {L_X, Γ, HR} → T_in IS independent of F_R given others → REMOVE edge T_in — F_R Test HR ⊥ F_R | {L_X, Γ} → HR is NOT independent of F_R given others → KEEP edge HR — F_R Uses Fisher's Z-test for partial correlation (appropriate for continuous Gaussian data = your telescope data)
Step 3 — Orient edges using v-structures
Pattern: Vᵢ — Vₖ — Vⱼ where Vᵢ and Vⱼ not connected → orient as Vᵢ → Vₖ ← Vⱼ (collider) This gives causal direction without intervention. Applied to your data to orient the remaining edges.
your specific causal graph results
REGIME 0 (Hard state, n=400): Edges after PC: L_X → F_R (β=+0.70, strong jet coupling) Γ → F_R (β=−0.22, spectral index drives jet) HR → F_R (β=−0.52, hardness suppresses jet) T_in ↛ F_R (removed — conditionally independent) REGIME 1 (Soft state, n=400): Edges after PC: L_X → F_R (β=+0.17, weaker coupling) Γ → F_R (β=+0.18) T_in → F_R (β=−0.40, NEW — absent in Regime 0) HR ↛ F_R (removed — jet decoupled from hardness)
why PC — not other causal discovery algorithms
LiNGAM — why not for P1
Assumes non-Gaussian noise for identifiability. Telescope measurement noise is Gaussian (photon counting → Poisson → Gaussian for large counts). LiNGAM loses its theoretical guarantees entirely on your data.
GES (Greedy Equivalence Search) — why not for P1
Score-based: searches over all DAG structures maximizing BIC. More computationally expensive than PC. Less interpretable. For p=5 variables with n=400 observations, PC is sufficient and more transparent.
FCI — why not
Extends PC to handle hidden confounders. More complex output (PAG not DAG). For P1 with clean synthetic data where confounders are known, FCI adds complexity without benefit.
PC — why yes
Designed for continuous Gaussian data. Uses Fisher's Z-test — exact match for telescope noise. Well-understood theoretically. Interpretable DAG output. Works well for p=5 variables with n=400 observations per regime. Implemented in causal-learn library.
PC needs STABLE data as input. If you ran PC on the full 800 mixed observations without splitting, it would find edges averaged across both regimes — missing T_in→F_R (only in soft state) and HR→F_R (only in hard state). Your partitioning is NOT optional preprocessing. It is the mathematical prerequisite for PC to produce correct results.
why this specific sequence of mathematical choices

Each component was chosen to solve a specific problem that the previous component left open. The pipeline is a chain of dependencies.

You have black hole data → need OLS
Black hole physics: F_R ∝ L_X^β (power law) Log transformation: log(F_R) = β·log(L_X) + ... = linear in log space Therefore: OLS is the exact correct model. OLS gives you: β̂, RSS for any group of observations. Problem remaining: is one β sufficient or are there hidden regimes?
Need to detect regime boundaries → need Chow test
You need to test: β(A) = β(B)? This is EXACTLY what the Chow test does. It uses RSS from OLS — so OLS must come first. Chow test gives you: F-statistic measuring mechanism difference. Problem remaining: which split is best? How to search?
Need to find the boundary → need greedy search
Evaluate Chow F for every candidate (j, τ). Pick argmax F. Search gives you: (j*=T_in, τ*=0.6425). Problem remaining: is this split real or noise?
Need to validate the split → need BIC
BIC compares: fit improvement vs complexity cost. Uses RSS from OLS — so OLS must come first. BIC gives you: accept or reject decision. Problem remaining: are there sub-regimes inside each group?
Need to check sub-regimes → need recursion
Run the entire pipeline again inside each accepted group. Independently. Recursively. Recursion gives you: K leaves = K discovered regimes. Problem remaining: which variable CAUSES which within each regime?
Need causal direction → need PC algorithm
OLS gives β — regression, not causation. PC uses conditional independence tests on stable group data. PC gives you: directed causal graph per regime. Problem remaining: nothing. Pipeline complete.
the complete dependency chain
Power law physics → Log transformation → LINEAR data → OLS is exact [fit quality: RSS, β] → Chow test is possible [regime detection: F-stat] → Greedy search is tractable [boundary finding: j*, τ*] → BIC validation is principled [noise rejection: accept/reject] → Recursion discovers K automatically [depth: K leaf nodes] → PC gives causal directions [science: G₁, G₂, ..., Gₖ] Remove any link → the chain breaks. Each component is necessary for the next to function.
The entire pipeline collapses if you change the base model from OLS to a neural network (no closed-form RSS → no Chow test → no split criterion → no tree). The choice of OLS is not conservative or limiting. It is the mathematical key that makes the entire downstream pipeline possible and theoretically grounded.
